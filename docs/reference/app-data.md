# Map data files

The public map reads its reference data from `app/data/` (`app/src/data.js`). The files are public: they hold no family data. The service worker precaches them, so a change needs a new version stamp (`node app/scripts/stamp-version.mjs`). Prettier skips the folder; `app/scripts/build-data.mjs` writes JSON in the layout of `app/scripts/lib/json-format.mjs`, and hand edits keep it.

| File                  | Edited                                  | Holds                                                                |
| --------------------- | --------------------------------------- | -------------------------------------------------------------------- |
| `archives.json`       | by hand, except `municipalityOverrides` | the archives that hold the parish registers, by district             |
| `layers.json`         | by hand                                 | the base map, the historical overlays and the historical map viewers |
| `districts.geojson`   | generated                               | 77 district (okres) polygons, as in 1960 to 2000                     |
| `country.geojson`     | generated                               | the border of the Czech Republic (all districts dissolved)           |
| `municipalities.json` | generated                               | every Municipality, for search and archive lookup                    |
| `build-info.json`     | generated                               | where the generated files came from, and what the build changed      |

## `archives.json`

| Key                     | Value                                                                                                                                                                        |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$comment`              | how to edit the file                                                                                                                                                         |
| `archives`              | the regional archives, one object each (below); together their `districts` cover every district exactly once                                                                 |
| `jewishRegisters`       | the archive that holds the Jewish registers of the whole Czech lands: `id`, `name`, `portal`, `placeSearchUrl`                                                               |
| `municipalityOverrides` | generated by `build-data.mjs`: Municipalities that keep the archive of their older district, by municipality code: `name`, `archive` (an archive `id`), `district`, `reason` |

An archive:

| Field            | Value                                                                                                                               |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `id`             | short identifier, such as `soa-praha`                                                                                               |
| `name`           | the archive's name                                                                                                                  |
| `shortName`      | optional: a shorter form of the name                                                                                                |
| `portal`         | `name` and `url` (`https://`) of the archive's online register portal                                                               |
| `placeSearchUrl` | a URL with `{name}` for the Municipality's name that opens a search in the portal, or `null` where no such pattern has been checked |
| `color`          | the region's colour on the archive regions layer, `#rrggbb`                                                                         |
| `districts`      | the districts whose registers the archive holds, named exactly as in `districts.geojson`                                            |

Archive lookup also names a second archive when its region is within 5 km of the place (`NEAR_BORDER_KM` in `app/src/archive-lookup.js`).

## `layers.json`

| Key        | Value                                                                                                                                                                            |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$comment` | how the layers are used                                                                                                                                                          |
| `base`     | the base map: `url` (tile URL with `{z}`, `{x}`, `{y}`), `referrerPolicy`, `attribution` (HTML), `maxZoom`                                                                       |
| `overlays` | historical map overlays, each a WMS service: `id`, `enabled`, `type` (`wms`), `url`, `layers`, `format`, `transparent`, `version`, `crs` (`EPSG:3857`), `opacity`, `attribution` |
| `viewers`  | links from a place sheet to historical map viewers: `id` and `url`, which may contain `{name}` for the Municipality's name                                                       |

Every URL must be `https://`. An overlay with `enabled: false` is neither drawn nor offered in the layers panel. The labels of overlays and viewers come from the app's translations (`overlay.<id>`, `viewer.<id>` in `app/i18n/`). The server allows the hosts of `base` and `overlays` in the app's Content-Security-Policy.

## `districts.geojson` and `country.geojson`

GeoJSON FeatureCollections in WGS 84. Each district has the properties `name` and `code`. The country file has one feature, named `Česko`. Both are simplified to 2 % of their points.

## `municipalities.json`

An array with one object per Municipality: `code` (the municipality code), `name`, `norm` (the name in lower case without diacritics, for search), `district`, `lat`, `lon`.

## `build-info.json`

| Key          | Value                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `sources`    | each downloaded source: `url`, `file`, `description`, `sha256`, `bytes` (and `rows` for the list of Municipalities) |
| `simplify`   | the polygon simplification used                                                                                     |
| `counts`     | districts and Municipalities written                                                                                |
| `excluded`   | rows of the source left out, with the reason                                                                        |
| `reassigned` | Municipalities listed under one district but inside another's polygon (district boundaries changed in 2021)         |
