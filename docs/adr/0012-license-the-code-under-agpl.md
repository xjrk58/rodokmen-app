# License the code under AGPL-3.0-or-later; data and vendored libraries keep their own licences

Rodokmen is an open-source app that each family hosts for itself (#56), so its code needs a licence that lets anyone run and change it. The code is licensed under the GNU Affero General Public License, version 3 or any later version (`AGPL-3.0-or-later`; the text is in `LICENSE`, the notice in `NOTICE`). We chose it to protect against closed hosted forks: nobody may run a changed Rodokmen as a service, for families or anyone else, and keep the changes to themselves. The consequence is that anyone who runs a modified version as a network service must offer its source to the people who use it, from the visitors of the public map to the Members of the Tree (§13), and anyone who passes copies on must do so under the same licence. A family that runs Rodokmen unchanged has no such duty, and its source is this public repo anyway. So that a changed copy meets that duty from the start, the app is to link to the source of the version it runs (#109). The licence covers code, not the Tree: a family's Persons, Sources, images and Exports are its own and never have to be published. The bundled map data in `app/data/` and the vendored libraries in `app/vendor/` keep their own licences, listed with the credit each asks for in docs/reference/licences.md. Share-alike data such as ODbL is not bundled today, and whether Country packs may bundle it is a separate decision (#63). Contributions come under the same licence as the code (inbound = outbound), with no copyright assignment, so the licence can change only with every contributor's consent or to a later AGPL version.

## Considered Options

- **Apache-2.0**: permissive, with a patent grant; rejected, because it allows closed hosted forks.
- **MIT**: the shortest and most permissive; rejected for the same reason.
- **A DCO sign-off on every commit**: not chosen; inbound = outbound needs no extra step from contributors.
